# Code Review Report

**Date**: 2025-11-27 13:37:53

이 리포트는 `REVIEW.md`의 지침에 따라 `exocortex` 프로젝트의 코드 가독성과 네이밍을 분석한 결과입니다.

## 1. 프로젝트 가독성 (General Readability)

프로젝트의 전반적인 구조는 **매우 직관적**입니다.

- **디렉토리 구조**: `model`, `server`, `schema` 등 역할에 따라 최상위 디렉토리가 명확히 구분되어 있어, 프로젝트를 처음 접하는 사람도 각 코드가 어디에 위치해야 하는지 쉽게 예측할 수 있습니다.
- **도메인 주도 설계**: `model` 내부가 `finance`, `portfolio` 등 도메인별로 나뉘어 있어, 비즈니스 로직의 응집도가 높습니다.

## 2. Model 네이밍 및 구조 (Naming & Structure in Model)

`model` 디렉토리의 파일 및 타입 네이밍은 일관성이 뛰어나며 이해하기 쉽습니다.

### 장점

- **명시적인 파일명**: 파일 이름이 해당 파일이 정의하는 핵심 타입을 그대로 반영합니다.
  - `quote.ts` → `Quote`
  - `deposit.ts` → `Deposit`
- **역할 기반 접미사**: 파일의 역할이 이름에 드러납니다.
  - `*.input.ts`: 데이터 입력/생성 시 사용되는 타입 (예: `deposit.input.ts`)
  - `*.projection.ts`: 특정 뷰나 로직을 위해 가공된 타입 (예: `fx.projection.ts`)
  - 이러한 규칙은 "어떤 데이터를 조회하는 타입"과 "어떤 데이터를 입력받는 타입"을 명확히 구분해주어 혼란을 줄입니다.
- **일관된 타입 정의**: `interface`와 `type` alias가 적절히 사용되고 있으며, `Nominal Types`(`nominal-types.ts`)를 활용하여 값의 의미(예: `USD`, `Percent`)를 명확히 하고 있습니다.

## 3. 개선 제안 및 아쉬운 점 (Minor Suggestions)

치명적이지 않지만, 차후 개선을 고려해볼 만한 사항들입니다.

- **`gendoc.api.ts` 위치**: 현재 루트에 위치해 있는데, `scripts/` 디렉토리 등을 만들어 관리용 스크립트들을 모아두면 루트 디렉토리가 더 깔끔해질 수 있습니다.
- **`server/index.ts`의 `Routes` 타입**: API 정의가 많아질수록 `Routes` 타입 정의가 매우 길어질 수 있습니다. 도메인별로 Route 타입을 분리하여 `index.ts`에서는 이를 합치는(merge) 형태로 리팩토링하면 유지보수성이 좋아질 것입니다.
- **`model/index.ts`의 re-export**: 모든 모델을 `index.ts`에서 re-export 하고 있습니다. 프로젝트 규모가 커지면 tree-shaking이나 모듈 로딩 속도에 미세한 영향을 줄 수 있으므로, 필요하다면 도메인별로 진입점(`model/finance/index.ts` 등)을 나누는 것도 고려해볼 만합니다.

## 총평

`exocortex`는 네이밍 규칙과 디렉토리 구조가 잘 잡혀 있어, 온보딩 비용이 낮은 훌륭한 프로젝트 구조를 가지고 있습니다. 현재의 컨벤션을 유지하면서 개발을 진행하면 될 것입니다.
